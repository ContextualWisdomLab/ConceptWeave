### Added

- PostgreSQL ordinary `EXCLUDE` constraint evidence now preserves raw `pg_proc.provolatile` for every exact governed `pg_operator.oprcode` implementation procedure in `IndexExclusionConstraintOperatorProcedureVolatilitySnapshot`. The successor is layered over the exact strictness predecessor, requires one independently observed volatility discriminator per exact constraint/key position, binds the repeated stable operator and exact implementation procedure to that predecessor, admits only PostgreSQL's raw `i`/`s`/`v` catalog states, and domain-separates all three. Missing/duplicate evidence, operator/procedure binding drift, zero position, unknown receipt coordinates, and unknown raw volatility values fail closed. This is observational evidence; it does not invent a local rule requiring ordinary EXCLUDE implementation procedures to be immutable.
- PostgreSQL ordinary `EXCLUDE` constraint evidence now preserves raw `pg_proc.proisstrict` for every exact governed `pg_operator.oprcode` implementation procedure in `IndexExclusionConstraintOperatorProcedureStrictnessSnapshot`. The successor is layered over the exact scalar-procedure predecessor, requires one independently observed strictness fact per exact constraint/key position, and binds the repeated stable operator and exact implementation procedure to that predecessor. Both `proisstrict=true` and `false` are admitted and domain-separated because PostgreSQL stores the flag independently and its exclusion executor assumes strict semantics without the ordinary EXCLUDE creation path establishing a separate strictness gate. Missing/duplicate evidence, operator/procedure binding drift, zero position, and unknown receipt coordinates fail closed; strictness is never inferred from Boolean return type, scalar cardinality, operator family, or executor behavior.
- PostgreSQL ordinary `EXCLUDE` constraint evidence now preserves raw `pg_proc.proretset` for every exact governed `pg_operator.oprcode` implementation procedure in `IndexExclusionConstraintOperatorProcedureScalarSnapshot`. The successor rebinds the raw operator-kind predecessor to the supplied result-contract predecessor, requires one independently observed scalar-cardinality fact per exact constraint/key position, binds the repeated stable operator and implementation procedure to the exact predecessor, and admits only `proretset=false`. Set-returning state, missing/duplicate evidence, operator/procedure binding drift, zero position, cross-predecessor mismatch, and unknown receipt coordinates fail closed. The raw flag enters a new domain-separated digest/provenance family; existing operator, commutator, procedure, result, kind, and earlier Source Observation digest domains remain unchanged.
- PostgreSQL ordinary `EXCLUDE` constraint evidence retains the raw `pg_operator.oprkind` discriminator for every exact governed `conexclop` key position in `IndexExclusionConstraintOperatorKindSnapshot`. The successor is layered over the exact Boolean result-contract predecessor, requires one independently observed raw kind per exact position, binds the repeated stable operator to the predecessor, and admits only PostgreSQL's binary `b` state. Prefix `l`, unknown kind, missing/duplicate position, zero position, operator-binding drift, and unknown receipt coordinates fail closed. The raw discriminator is never inferred from normalized left/right operand types, operator name, commutator state, operator-family membership, strategy, or implementation procedure.
