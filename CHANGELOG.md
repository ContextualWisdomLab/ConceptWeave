### Added

- PostgreSQL ordinary `EXCLUDE` constraint evidence now preserves raw `pg_proc.prokind` for every exact governed `pg_operator.oprcode` implementation routine in `IndexExclusionConstraintOperatorProcedureKindSnapshot`. The successor is layered over the exact procedure-parallel-safety predecessor, requires one independently observed routine-kind discriminator per exact constraint/key position, binds the repeated stable operator and exact implementation routine to that predecessor, and admits only PostgreSQL normal-function kind `f`. Procedure `p`, aggregate `a`, window-function `w`, unknown values, missing/duplicate evidence, operator/procedure binding drift, zero positions, and unknown receipt coordinates fail closed. This mirrors PostgreSQL `CREATE OPERATOR`, which requires the implementation object to be a function even when its legacy syntax spells the clause `PROCEDURE`; routine kind is never inferred from normalized signature or auxiliary `pg_proc` properties.
- PostgreSQL ordinary `EXCLUDE` constraint evidence preserves raw `pg_proc.proparallel` for every exact governed `pg_operator.oprcode` implementation procedure in `IndexExclusionConstraintOperatorProcedureParallelSafetySnapshot`. The successor is layered over the exact procedure-volatility predecessor, requires one independently observed parallel-safety discriminator per exact constraint/key position, binds the repeated stable operator and exact implementation procedure to that predecessor, admits only PostgreSQL's raw `s`/`r`/`u` catalog states, and domain-separates all three. Missing/duplicate evidence, operator/procedure binding drift, zero position, unknown receipt coordinates, and unknown raw parallel-safety values fail closed. This is observational evidence; it does not invent a local rule requiring ordinary EXCLUDE implementation procedures to be parallel safe.
- PostgreSQL ordinary `EXCLUDE` constraint evidence preserves raw `pg_proc.provolatile`, raw `pg_proc.proisstrict`, raw scalar `pg_proc.proretset=false`, and raw binary `pg_operator.oprkind` in their existing domain-separated successors. Their prior contracts remain authoritative and unchanged by the procedure-kind successor.
