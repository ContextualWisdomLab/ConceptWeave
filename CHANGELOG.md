## Unreleased

### Added

- PostgreSQL ordinary `EXCLUDE` constraint evidence now preserves exact `pg_constraint.conenforced` in a domain-separated `IndexExclusionConstraintEnforcementSnapshot` layered over the exact EXCLUDE timing predecessor. Every governed ordinary exclusion constraint requires one explicit enforcement observation; PostgreSQL 18 source-unreachable `conenforced=false` fails closed, the raw bit remains in the successor digest and provenance receipt, temporal PRIMARY KEY/UNIQUE `WITHOUT OVERLAPS` remains owned by the key-constraint family, and no issued predecessor digest domain is rewritten.
- PostgreSQL ordinary `EXCLUDE` constraint evidence now preserves exact `pg_constraint.convalidated` in a domain-separated `IndexExclusionConstraintValidationSnapshot` layered over the exact enforcement predecessor. Every governed ordinary exclusion constraint requires one explicit validation observation; the PostgreSQL 18 index-constraint creation path's contradictory `convalidated=false` state fails closed, the raw bit remains in the successor digest and provenance receipt, and no issued predecessor digest domain is rewritten.
- PostgreSQL ordinary `EXCLUDE` constraint evidence now preserves exact `pg_constraint.connoinherit` in a domain-separated `IndexExclusionConstraintNoInheritSnapshot` bound to the exact EXCLUDE identity predecessor. Every predecessor constraint requires one explicit raw observation and the bit is retained in a separate digest/provenance receipt; PostgreSQL attach/detach lifecycle can change parentage without rewriting `connoinherit`, so the snapshot preserves either source-reachable boolean state rather than deriving it from current parentage.
- PostgreSQL ordinary `EXCLUDE` constraint evidence now preserves exact `pg_constraint.conperiod` in a domain-separated `IndexExclusionConstraintPeriodSnapshot` bound to the exact ordinary-EXCLUDE identity predecessor. Every predecessor ordinary exclusion constraint requires one explicit period-state observation; `conperiod=true` fails closed because PostgreSQL 18 reserves that state for `WITHOUT OVERLAPS` PRIMARY KEY/UNIQUE and `PERIOD` FOREIGN KEY constraints, while temporal p/u/f semantics remain owned by `ConstraintPeriodObservation` and no issued predecessor digest domain is rewritten.
- PostgreSQL ordinary `EXCLUDE` constraint evidence now preserves exact `pg_constraint.conkey` in a domain-separated `IndexExclusionConstraintKeySnapshot`. The successor first rebuilds and digest-checks the supplied v3/relation-partition/index-partition/ordinary-EXCLUDE predecessor chain, then rebound-validates the exact period predecessor. Every ordinary exclusion constraint requires one explicit ordered `int2[]`; simple columns must match the backing index's relation attribute numbers, expression positions remain zero, INCLUDE payload positions are excluded, and the raw vector is bound into the successor digest and provenance receipt without rewriting any issued predecessor domain.
- PostgreSQL ordinary `EXCLUDE` constraint evidence now preserves independently stored `pg_constraint.conexclop` in a domain-separated `IndexExclusionConstraintOperatorSnapshot`. Capture-time operator OIDs are resolved to stable schema/name/operand-type signatures; every ordinary `contype='x'` coordinate requires one complete ordered vector, and that constraint-side vector must equal the exact exclusion operators independently governed for its `conindid` backing index. The successor rebinds both predecessor branches, keeps temporal PRIMARY KEY/UNIQUE `WITHOUT OVERLAPS` in the key-constraint family, and does not rewrite any issued predecessor digest domain.
- PostgreSQL ordinary `EXCLUDE` constraint timing now has an explicit cross-catalog coherence successor: `IndexExclusionConstraintImmediacySnapshot` independently rebinds `pg_constraint.condeferrable` and the exact `conindid` backing index's `pg_index.indimmediate`, failing closed unless `indimmediate = !condeferrable`. `DEFERRABLE INITIALLY IMMEDIATE` and `DEFERRABLE INITIALLY DEFERRED` both retain `indimmediate=false` while remaining distinct through the timing predecessor digest; neither catalog fact is inferred from the other and no issued predecessor digest domain is rewritten.
