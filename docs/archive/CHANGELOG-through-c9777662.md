# Changelog

## Unreleased

### Added

- PostgreSQL ordinary `EXCLUDE` constraint evidence now preserves exact `pg_constraint.conenforced` in a domain-separated `IndexExclusionConstraintEnforcementSnapshot` layered over the exact EXCLUDE timing predecessor. Every governed ordinary exclusion constraint requires one explicit enforcement observation; PostgreSQL 18 source-unreachable `conenforced=false` fails closed, the raw bit remains in the successor digest and provenance receipt, temporal PRIMARY KEY/UNIQUE `WITHOUT OVERLAPS` remains owned by the key-constraint family, and no issued predecessor digest domain is rewritten.
- PostgreSQL ordinary `EXCLUDE` constraint evidence now preserves exact `pg_constraint.convalidated` in a domain-separated `IndexExclusionConstraintValidationSnapshot` layered over the exact enforcement predecessor. Every governed ordinary exclusion constraint requires one explicit validation observation; the PostgreSQL 18 index-constraint creation path's contradictory `convalidated=false` state fails closed, the raw bit remains in the successor digest and provenance receipt, and no issued predecessor digest domain is rewritten.
- PostgreSQL ordinary `EXCLUDE` constraint evidence now preserves exact `pg_constraint.connoinherit` in a domain-separated `IndexExclusionConstraintNoInheritSnapshot` bound to the exact EXCLUDE identity predecessor. Every predecessor constraint requires one explicit raw observation and the bit is retained in a separate digest/provenance receipt; PostgreSQL attach/detach lifecycle can change parentage without rewriting `connoinherit`, so the snapshot preserves either source-reachable boolean state rather than deriving it from current parentage.
- PostgreSQL ordinary `EXCLUDE` constraint evidence now preserves exact `pg_constraint.conperiod` in a domain-separated `IndexExclusionConstraintPeriodSnapshot` bound to the exact ordinary-EXCLUDE identity predecessor. Every predecessor ordinary exclusion constraint requires one explicit period-state observation; `conperiod=true` fails closed because PostgreSQL 18 reserves that state for `WITHOUT OVERLAPS` PRIMARY KEY/UNIQUE and `PERIOD` FOREIGN KEY constraints, while temporal p/u/f semantics remain owned by `ConstraintPeriodObservation` and no issued predecessor digest domain is rewritten.
- PostgreSQL ordinary `EXCLUDE` constraint evidence now preserves exact `pg_constraint.conkey` in a domain-separated `IndexExclusionConstraintKeySnapshot`. The successor first rebuilds and digest-checks the supplied v3/relation-partition/index-partition/ordinary-EXCLUDE predecessor chain, then rebound-validates the exact period predecessor. Every ordinary exclusion constraint requires one explicit ordered `int2[]`; simple columns must match the backing index's relation attribute numbers, expression positions remain zero, INCLUDE payload positions are excluded, and the raw vector is bound into the successor digest and provenance receipt without rewriting any issued predecessor domain.
- PostgreSQL ordinary `EXCLUDE` constraint evidence now preserves independently stored `pg_constraint.conexclop` in a domain-separated `IndexExclusionConstraintOperatorSnapshot`. Capture-time operator OIDs are resolved to stable schema/name/operand-type signatures; every ordinary `contype='x'` coordinate requires one complete ordered vector, and that constraint-side vector must equal the exact exclusion operators independently governed for its `conindid` backing index. The successor rebinds both predecessor branches, keeps temporal PRIMARY KEY/UNIQUE `WITHOUT OVERLAPS` in the key-constraint family, and does not rewrite any issued predecessor digest domain.
- PostgreSQL ordinary `EXCLUDE` constraint timing now has an explicit cross-catalog coherence successor: `IndexExclusionConstraintImmediacySnapshot` independently rebinds `pg_constraint.condeferrable` and the exact `conindid` backing index's `pg_index.indimmediate`, failing closed unless `indimmediate = !condeferrable`. `DEFERRABLE INITIALLY IMMEDIATE` and `DEFERRABLE INITIALLY DEFERRED` both retain `indimmediate=false` while remaining distinct through the timing predecessor digest; neither catalog fact is inferred from the other and no issued predecessor digest domain is rewritten.
- PostgreSQL ordinary `EXCLUDE` constraint backing indexes now have an explicit role-coherence successor: `IndexExclusionConstraintIndexRoleSnapshot` rebinds the exact ordinary-EXCLUDE and timing/immediacy chain, retains independently observed `pg_index.indisunique`, `indisprimary`, and `indisexclusion`, and fails closed unless the exact `conindid` backing index is `(false, false, true)`. Temporal PRIMARY KEY/UNIQUE `WITHOUT OVERLAPS` remains in the key-constraint owner family, and no issued predecessor digest domain is rewritten.
- PostgreSQL ordinary `EXCLUDE` constraint admission now enforces relation-wide `pg_constraint.conname` integrity across the base PRIMARY KEY/UNIQUE/FOREIGN KEY/CHECK families and explicitly observed PostgreSQL 18 first-class NOT NULL rows. Same-relation cross-family name collisions fail closed before EXCLUDE digest/receipt issuance; cross-relation textual reuse remains a relation-local `pg_constraint` concern for non-index constraints, while the schema-scoped backing-index namespace of index-backed EXCLUDE constraints is validated separately. Unobserved NOT NULL evidence is never invented, and issued digest algorithms are unchanged.
- PostgreSQL ordinary `EXCLUDE` constraint evidence now independently retains resolved `pg_constraint.connamespace` in `IndexExclusionConstraintNamespaceSnapshot`. Every predecessor ordinary exclusion constraint requires one explicit namespace observation; the resolved namespace must equal the owning relation schema as required by PostgreSQL 18's index-constraint creation path. The raw resolved namespace is bound into a new digest/provenance domain rather than being synthesized from relation metadata or rewriting an issued predecessor digest; index-backed name/schema-namespace integrity is validated separately.
- PostgreSQL ordinary `EXCLUDE` constraint evidence now validates the mutually exclusive `pg_constraint` family shape in `IndexExclusionConstraintCatalogShapeSnapshot`: exact `contype='x'`, nonzero relation ownership, zero domain ownership, non-FK space action sentinels, no FK-only relation/column/operator/delete-set payload, and no CHECK expression. Every predecessor ordinary EXCLUDE coordinate requires one explicit family-shape observation, the raw sentinels/presence state are bound into a new digest/provenance domain, and existing exact `conkey`/`conexclop` successors remain the sole owners of those ordered arrays.
- PostgreSQL ordinary `EXCLUDE` constraint evidence now validates the independently observed `pg_constraint.conname` against the exact resolved `conindid` backing index `pg_class.relname` in `IndexExclusionConstraintIndexNameSnapshot`. The two names must match exactly, that backing-index name must occupy exactly one observed index slot in the authorized schema, and it must not collide with any separately observed top-level `pg_class` relation name. The successor rebinds the exact ordinary-EXCLUDE and catalog-family-shape predecessors, keeps non-index constraint-name semantics relation-local, and binds both source coordinates into a new digest/provenance domain without rewriting issued predecessor digests.
- PostgreSQL ordinary `EXCLUDE` constraint evidence now requires independently observed backing access-method exclusion capability in `IndexExclusionConstraintAccessMethodCapabilitySnapshot`. The successor rebinds the exact v3/relation-partition/index-partition/ordinary-EXCLUDE chain, binds the exact `conindid` coordinate and observed access-method name, and fails closed unless `pg_indexam_has_property(am_oid, 'can_exclude')` is true. Capability is never inferred from `indisexclusion`, operator semantics, or a built-in access-method allowlist, so extension AMs remain valid when their own handler reports support.
- PostgreSQL ordinary `EXCLUDE` constraint evidence now preserves independently resolved `pg_operator.oprcom` commutator state for every exact `conexclop` key position in `IndexExclusionConstraintOperatorCommutatorSnapshot`. The successor binds each independently resolved commutator to the exact governed operator position and fails closed unless it resolves to the same stable schema/name/operand-type signature, matching PostgreSQL 18's self-commutator requirement. Capture-time OIDs remain adapter-local; commutativity is never inferred from operator names, operator-family membership, strategy numbers, or procedures, and existing issued digest domains remain unchanged.
- PostgreSQL ordinary `EXCLUDE` constraint evidence now independently preserves the exact `conindid` backing index row's resolved `pg_class.relnamespace` in `IndexExclusionConstraintIndexNamespaceSnapshot`. The successor requires one explicit namespace observation for every exact constraint/index binding already proven by `IndexExclusionConstraintIndexNameSnapshot`, rejects missing/duplicate or wrong-index evidence, and fails closed when the resolved index namespace differs from the parent relation/index coordinate. The namespace and both exact source coordinates are bound into a new digest/provenance domain; relation or constraint namespace must not be copied into this evidence.
- PostgreSQL ordinary `EXCLUDE` constraint evidence now binds the exact `conindid` backing index's independently observed `pg_index.indisready`, `indisvalid`, and `indislive` state in `IndexExclusionConstraintIndexLifecycleSnapshot`. The successor composes the current backing-index namespace generation with the exact same v3 source-content generation, fails closed for missing lifecycle bits, any non-ready/invalid/non-live backing index, another exact index, mismatched source metadata, or a different v3 content digest, and retains both predecessor/base digests plus the raw lifecycle vector in a new provenance domain. `IndexExclusionConstraintIndexNameSnapshot` and `IndexExclusionConstraintIndexNamespaceSnapshot` now carry the immutable v3 source digest as predecessor metadata without changing their issued digest calculations; `indcheckxmin` remains separately retained catalog evidence rather than being misclassified as the same lifecycle predicate.
- PostgreSQL ordinary `EXCLUDE` constraint evidence now preserves the independently resolved `pg_operator.oprcode -> pg_proc` implementation-function signature for every exact `conexclop` key position in `IndexExclusionConstraintOperatorProcedureSnapshot`. The operator predecessor retains the already-rebound backing exclusion procedure as immutable metadata without changing its issued digest; the successor rejects missing/duplicate positions, operator drift, and a same-typed but different function unless the independently resolved `oprcode` procedure equals the backing exclusion procedure. Capture-time OIDs remain adapter-local and the new procedure edge uses its own domain-separated digest/provenance family.
- PostgreSQL ordinary `EXCLUDE` constraint evidence now preserves independently resolved `pg_operator.oprresult` and `pg_proc.prorettype` for every exact governed `conexclop` position in `IndexExclusionConstraintOperatorResultSnapshot`. The successor binds those facts to the exact operator and `oprcode` procedure predecessor, requires both resolved result types to agree and identify `pg_catalog.bool`, and fails closed on mismatched results, matching non-Boolean results, wrong-schema lookalike `bool`, missing/duplicate positions, or operator/procedure binding drift. The result contract has its own digest/provenance family and does not rewrite any issued predecessor identity.
