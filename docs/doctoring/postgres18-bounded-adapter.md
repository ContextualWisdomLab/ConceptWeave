# PostgreSQL 18 bounded observation path

`conceptweave-postgres-adapter` consumes a single registry-authorized Source Observation capability. Its connection map holds one current policy binding and credential-bearing `tokio-postgres::Config` per source key. An older binding fails before source I/O. Credentials remain adapter-local. `PostgresUnixAdapter` accepts Unix sockets only. `PostgresTlsAdapter` accepts TCP hosts only, requires one DER CA trust anchor per binding, forces TLS, and verifies the server certificate chain and configured host name. Invalid anchors, mixed transports, stale bindings, certificate failures, and host-name mismatches fail closed. The trust anchor and connection configuration remain adapter-local; neither enters the snapshot.

The adapter opens one `REPEATABLE READ READ ONLY` transaction, fixes `search_path` to `pg_catalog`, sets local server timeouts, and checks the server major version and transaction mode. It verifies every requested schema exists in that transaction. It reads qualified domain base types and collations, type modifiers, array dimensions, null/default state, comments, domain CHECK definitions and validation/enforcement flags, and enum labels in catalog order. It records every schema-local true-array pair and the `pg_catalog` true-array pairs referenced by captured columns or domain bases, checking exact reciprocal `typarray`/`typelem` coordinates. For each schema-local range, a separate successor digest binds its exact subtype, B-tree operator class, comparison collation, and optional canonical and difference procedure coordinates. A later successor digest binds server-reconstructed definitions and owners of referenced range procedures without retaining their source text in the snapshot. Explicit procedure ACLs, comments, security labels, and extension membership fail closed; procedure dependency closure remains outside this bounded range slice. Referenced range collations receive complete collation-definition evidence. PostgreSQL 18 RED/GREEN fixtures change a range subtype and a difference-function body under the same names and prove changed source identity; a text-range fixture checks collation and difference-function capture. It also admits ordinary permanent tables and standalone composite-type relations with exact column order, qualified type binding, rendered type text, nullability, comments, and exact column collation identity and determinism. Table replica-identity mode remains table-only evidence. Every column carries explicit uncollatable or qualified collatable evidence; a nonzero catalog collation without a matching catalog row fails closed. Unknown domain constraint kinds and unmodeled domain CHECK ownership, timing, comments, security labels, or extension membership fail closed. A PostgreSQL 18 fixture verifies that commenting on a domain CHECK cannot retain an admitted observation. Catalog OIDs are used only for joins within that transaction; immutable identity uses exact qualified names and observed content.

The table path admits only the built-in `heap` table access method with its PostgreSQL handler, and rejects partitioned/inherited, typed, temporary or unlogged, security-enabled, option-bearing, ACL-bearing, rule-bearing, user-trigger-bearing, unknown-internal-trigger-bearing, or extension-owned relations. Rule and trigger catalog rows decide admission because `pg_class.relhasrules` and `relhastriggers` can remain true after deletion. It admits local table CHECK constraints with their reconstructed definition and validation, enforcement, and inheritance flags, requiring `pg_class.relchecks` to match captured rows. It captures every ordinary-table `pg_constraint.contype = 'n'` row as a distinct NOT NULL successor fact and requires one for every nonnullable column. It also admits ordinary validated and enforced PRIMARY KEY and UNIQUE constraints, preserving exact NOT DEFERRABLE, INITIALLY IMMEDIATE, or INITIALLY DEFERRED timing. It resolves ordered `conkey` positions to exact columns and checks backing-index name, ordered key shape, lifecycle, immediacy, and NULL comparison behavior. A deferrable key must have exactly one PostgreSQL internal `unique_key_recheck` trigger bound to that constraint and backing index; other trigger rows fail closed. The PostgreSQL 18 [`pg_trigger` bit layout](https://github.com/postgres/postgres/blob/REL_18_STABLE/src/include/catalog/pg_trigger.h) defines the row/insert/update trigger shape used by this guard. The same catalog queries prove `conperiod=false` for each admitted PRIMARY KEY, UNIQUE, and FOREIGN KEY; the snapshot records that explicit evidence, and discovery requires the complete PERIOD observation family. Constraint comments and security labels, exclusion, temporal, and nondefault key-constraint variants still fail closed. Its index path admits permanent ordinary indexes with column and expression keys, INCLUDE columns, partial predicates, and exact access-method names. Key positions remain distinct from INCLUDE positions; a zero `indkey` entry is captured as the server-rendered expression at that exact position. Index storage and key-level operator-class options are preserved as exact `keyword=value` catalog entries; access-method option bits remain uninterpreted. Index ACLs, security labels, extension ownership, and an explicit index-expression statistics target still fail closed. It captures each key's exact qualified collation and operator class, raw option bits, uniqueness/null semantics, lifecycle flags, resolved tablespace, reconstructed definition, and comment. The owner rejects impossible replica-identity index flags on nonunique indexes and at aggregate completion checks that a flagged index is immediate, nonpartial, and uses only NOT NULL column keys. Nullable INCLUDE payloads remain valid. It records every column identity mode and, for identity columns, the internally owned sequence name, data type, start, increment, bounds, cache, cycle, and comment from the same transaction. A missing or duplicate internal sequence, changed owner, nondefault sequence ACL/options, security label, or extension ownership fails closed. SQL-invisible dropped-column tombstones are omitted without renumbering surviving attribute positions. ACL-bearing, option-bearing, or missing-value-bearing columns still fail closed. Ordinary tables and standalone composites require reciprocal `pg_class.reltype`/`pg_type.typrelid` identity and no unmodeled row-type ACL, type comment, security label, or extension ownership. Every type in an admitted schema also rejects unmodeled ACLs, security labels, extension ownership, and comments outside captured domain/enum definitions; a PostgreSQL 18 fixture confirms domain and enum ACL changes fail closed. Standalone composites additionally require no storage; their table-only constraints and indexes must be absent. Other modeled relation kinds fail closed. Defaults and stored or virtual generated expressions are captured for every column; their dependencies are not inferred from rendered text. Referenced column, domain, and index-key collations now carry a successor definition digest with exact provider, encoding, deterministic mode, locale fields, ICU rules, stored version, actual provider version, and catalog comment. The `pg_catalog.default` entry also binds the effective database locale and version; impossible provider/locale field combinations fail closed. The adapter checks text size on the server before returning catalog fields; security-labeled or extension-owned collations fail closed. Unreferenced schema collations and collation-owner authorization metadata remain outside this bounded path.

Rows are streamed and checked against the authorized row and retained-byte ceilings before snapshot construction. Oversized reconstructed defaults, generated expressions, index definitions/predicates, option arrays, comments, or CHECK definitions are rejected by server-side byte checks without returning their text. Every connect, transaction, query, stream read, and commit is bounded by the non-resetting operation budget and cooperative cancellation. Failed capture drops the transaction and connection without publishing a snapshot.

The adapter admits ordinary PostgreSQL 18 FOREIGN KEY constraints only when the referenced table is inside the authorized observed scope. It binds each FK to the selected referenced unique index and all three ordered equality-operator arrays using qualified operator signatures. The complete FK family changes successor source identity, and the owner checks referenced-index coherence. Both sides of every FK must have exactly the expected PostgreSQL internal referential triggers, with matching action, firing shape, index, deferrability, and counterpart relation. Incoming FKs from unobserved tables fail closed. PERIOD and unsupported catalog variants remain outside this bounded path.

The transport dependency is pinned to `tokio-postgres =0.7.18` in `Cargo.lock`, the first patched version for [GHSA-3gjw-f78c-vvpw](https://github.com/advisories/GHSA-3gjw-f78c-vvpw). TLS uses `rustls =0.23.45`, which fixes [RUSTSEC-2026-0285](https://rustsec.org/advisories/RUSTSEC-2026-0285). `cargo deny check advisories` passed on 2026-09-25. The [PostgreSQL 18 type](https://www.postgresql.org/docs/18/catalog-pg-type.html), [enum](https://www.postgresql.org/docs/18/catalog-pg-enum.html), [index](https://www.postgresql.org/docs/18/catalog-pg-index.html), [class](https://www.postgresql.org/docs/18/catalog-pg-class.html), and [constraint](https://www.postgresql.org/docs/18/catalog-pg-constraint.html) catalogs define the captured fields.

Run the local PostgreSQL 18 fixture with `CONCEPTWEAVE_PG18_TEST_DSN='host=/tmp dbname=postgres' cargo +1.98.0 test -p conceptweave-postgres-adapter --test postgres18_capture`. The fixture creates and removes two dedicated schemas. It checks domain/enum, table/column and default, explicit, and nondeterministic ICU collation evidence, CHECK, NOT NULL, PRIMARY KEY and UNIQUE constraint, and index receipts; changed digests after live enum/domain, column-default/comment, CHECK validation, NOT NULL add/validate/drop, PRIMARY KEY and UNIQUE creation, and index-comment changes; stored and virtual generated-column evidence; a unique `NULLS NOT DISTINCT` index; mixed column/expression keys with INCLUDE and a partial predicate; exact quoted whitespace identifiers; same-name enums in separate schemas; input-order-independent identity; row and byte ceilings; exact capture of a Hash index and a B-tree fillfactor change. It distinguishes INITIALLY IMMEDIATE and INITIALLY DEFERRED UNIQUE digests, verifies the internal recheck trigger, and rejects a user trigger or explicit expression statistics target. A live custom-table-access-method fixture verifies fail-closed admission; the identity fixture compares all sequence settings with `pg_sequence` and verifies changed digests after an increment, sequence comment, or generation-mode edit. A separate live FK fixture checks a composite relationship, selected referenced index, equality operators, targeted `ON DELETE SET NULL`, delayed enforcement, stable replay digest, changed digests after changing actions/timing and validating a `MATCH FULL NOT VALID` constraint, and rejection of an out-of-scope referenced table. A separate live collation fixture proves that `ALTER COLLATION ... REFRESH VERSION` changes source identity while the qualified collation name and determinism remain the same. It admits the table again after the user trigger is dropped despite PostgreSQL's stale hint. Without the environment variable, that server test is skipped.

The checked-in `tests/fixtures/grc_shape.sql` contains an anonymized tenant/risk/control/link schema without application rows. Its live PostgreSQL 18 replay verifies four observed tables, one domain, one enum, four foreign keys, exact `conperiod` coordinates for every key and foreign key, an exact constraint receipt, stable digest across observations, changed digest after a column comment edit, and restoration of the original digest after reversing that edit. It compares index key/INCLUDE counts and order, partial predicates, catalog flags, NOT NULL constraint rows, domain base/settings/CHECK rows, and ordered enum labels with fresh PostgreSQL catalog reads. It queries only the dedicated fixture schema through the adapter.

The TCP fixture uses an isolated PostgreSQL 18 instance configured with `ssl=on`, a server certificate for `localhost`, and `hostssl` access only. Set `CONCEPTWEAVE_PG18_TLS_TEST_DSN='host=localhost port=<port> dbname=postgres'`, `CONCEPTWEAVE_PG18_TLS_CA_DER=<DER CA certificate path>`, `CONCEPTWEAVE_PG18_TLS_WRONG_CA_DER=<unrelated DER CA certificate path>`, and `CONCEPTWEAVE_PG18_PLAINTEXT_TEST_DSN='host=localhost port=<plain server port> dbname=postgres'` for the same test command. The plaintext server must have `ssl=off`. It proves that the authorized observation succeeds with the correct CA and host, while an unrelated CA, an IP host absent from the certificate, and a server without TLS all fail. The test is skipped unless all four variables are set.

This path does not admit general relation-bearing schemas. Discovery maps ordinary tables to table concepts and standalone composite relations to separate source-type concept candidates. Any nonempty relational or type-only proposal now requires explicit true-array, type-kind, and collation-definition observation, including a matching composite type row for each proposed table or standalone composite and matching type rows for each domain and enum. An older v3 snapshot with an unobserved or incomplete type-kind family remains representable but cannot become a reviewable proposal. The live composite fixture checks separate attribute candidates, exact column receipts, required alignment decisions, parent validation, steward-review digest binding, durable publication, signed release admission, and pinned client readback; other relation kinds remain outside this bounded path. It does not establish the required complete PostgreSQL adapter, independent approval, hosted Product checks, or same-generation differential over the full model.

Tables assigned to a nondefault tablespace fail capture until the relation identity can retain the exact table-level tablespace coordinate. The live PostgreSQL 18 fixture verifies this after moving an otherwise admitted table.

The live quoted-identifier fixture preserves whitespace, slash, and tilde in observed schema/relation/column/constraint/index/domain/enum names, and verifies distinct receipt coordinates for text that resembles an escaped pointer token.

The column-collation fixture compares the captured database-default collation against PostgreSQL 18's actual provider-`d`, encoding-`-1` catalog row and the current database locale/version fields.
