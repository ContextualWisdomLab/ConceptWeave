# PostgreSQL 18 bounded observation path

`conceptweave-postgres-adapter` consumes a single registry-authorized Source Observation capability. Its connection map holds one current policy binding and credential-bearing `tokio-postgres::Config` per source key. An older binding fails before source I/O. Credentials remain adapter-local. `PostgresUnixAdapter` accepts Unix sockets only and rejects `hostaddr`, which the pinned driver otherwise prefers over a Unix `host` when choosing a TCP connection. `PostgresTlsAdapter` accepts TCP hosts only, requires one DER CA trust anchor per binding, forces TLS, and verifies the server certificate chain and configured host name. Invalid anchors, mixed transports, stale bindings, certificate failures, and host-name mismatches fail closed. The trust anchor and connection configuration remain adapter-local; neither enters the snapshot.

The adapter opens one `REPEATABLE READ READ ONLY` transaction, fixes `search_path` to `pg_catalog`, sets local server timeouts, and checks the server major version and transaction mode. It verifies every requested schema exists in that transaction. It reads qualified domain base types and collations, type modifiers, array dimensions, null/default state, comments, domain CHECK definitions and validation/enforcement flags, and enum labels in catalog order. It records every schema-local true-array pair and the `pg_catalog` true-array pairs referenced by captured columns or domain bases, checking exact reciprocal `typarray`/`typelem` coordinates. For each schema-local range, a separate successor digest binds its exact subtype, B-tree operator class, comparison collation, and optional canonical and difference procedure coordinates. A later successor digest binds server-reconstructed definitions and owners of referenced range procedures without retaining their source text in the snapshot. [PostgreSQL 18 tracks body dependencies for SQL-standard function bodies but not string bodies](https://www.postgresql.org/docs/18/sql-createfunction.html). Referenced user-defined range procedures therefore require a parsed SQL body and no unmodeled user-object dependencies; string bodies, custom function calls, and other unbound dependencies fail closed. A live RED fixture changed a helper function while the prior range digest stayed fixed; the guarded adapter rejects the incomplete capture. Explicit procedure ACLs, comments, security labels, and extension membership also fail closed. Referenced range collations receive complete collation-definition evidence. PostgreSQL 18 fixtures change a range subtype and a safely parsed difference-function body under the same names and prove changed source identity; a text-range fixture checks collation and difference-function capture. It also admits ordinary permanent tables and standalone composite-type relations with exact column order, qualified type binding, rendered type text, nullability, comments, and exact column collation identity and determinism. Table replica-identity mode remains table-only evidence. Every column carries explicit uncollatable or qualified collatable evidence; a nonzero catalog collation without a matching catalog row fails closed. Unknown domain constraint kinds and unmodeled domain CHECK ownership, timing, comments, security labels, or extension membership fail closed. A PostgreSQL 18 fixture verifies that commenting on a domain CHECK cannot retain an admitted observation. Catalog OIDs are used only for joins within that transaction; immutable identity uses exact qualified names and observed content.

The table path admits only the built-in `heap` table access method with its PostgreSQL handler, and rejects partitioned/inherited, typed, temporary or unlogged, security-enabled, option-bearing, ACL-bearing, rule-bearing, user-trigger-bearing, unknown-internal-trigger-bearing, or extension-owned relations. Rule and trigger catalog rows decide admission because `pg_class.relhasrules` and `relhastriggers` can remain true after deletion. It admits local table CHECK constraints with their reconstructed definition and validation, enforcement, and inheritance flags, requiring `pg_class.relchecks` to match captured rows. It captures every ordinary-table `pg_constraint.contype = 'n'` row as a distinct NOT NULL successor fact and requires one for every nonnullable column. It also admits ordinary validated and enforced PRIMARY KEY and UNIQUE constraints, preserving exact NOT DEFERRABLE, INITIALLY IMMEDIATE, or INITIALLY DEFERRED timing. It resolves ordered `conkey` positions to exact columns and checks backing-index name, ordered key shape, lifecycle, immediacy, and NULL comparison behavior. A deferrable key must have exactly one PostgreSQL internal `unique_key_recheck` trigger bound to that constraint and backing index; other trigger rows fail closed. The PostgreSQL 18 [`pg_trigger` bit layout](https://github.com/postgres/postgres/blob/REL_18_STABLE/src/include/catalog/pg_trigger.h) defines the row/insert/update trigger shape used by this guard. The same catalog queries prove `conperiod=false` for each admitted PRIMARY KEY, UNIQUE, and FOREIGN KEY; the snapshot records that explicit evidence, and discovery requires the complete PERIOD observation family. Constraint comments and security labels, exclusion, temporal, and nondefault key-constraint variants still fail closed. Its index path admits permanent ordinary indexes with column and expression keys, INCLUDE columns, partial predicates, and exact access-method names. Key positions remain distinct from INCLUDE positions; a zero `indkey` entry is captured as the server-rendered expression at that exact position. Index storage and key-level operator-class options are preserved as exact `keyword=value` catalog entries; access-method option bits remain uninterpreted. Index ACLs, security labels, extension ownership, and an explicit index-expression statistics target still fail closed. It captures each key's exact qualified collation and operator class, raw option bits, uniqueness/null semantics, lifecycle flags, resolved tablespace, reconstructed definition, and comment. The owner rejects impossible replica-identity index flags on nonunique indexes and at aggregate completion checks that a flagged index is immediate, nonpartial, and uses only NOT NULL column keys. Nullable INCLUDE payloads remain valid. It records every column identity mode and, for identity columns, the internally owned sequence name, data type, start, increment, bounds, cache, cycle, and comment from the same transaction. A missing or duplicate internal sequence, changed owner, nondefault sequence ACL/options, security label, or extension ownership fails closed. SQL-invisible dropped-column tombstones are omitted without renumbering surviving attribute positions. ACL-bearing, option-bearing, or missing-value-bearing columns still fail closed. Ordinary tables and standalone composites require reciprocal `pg_class.reltype`/`pg_type.typrelid` identity and no unmodeled row-type ACL, type comment, security label, or extension ownership. Every type in an admitted schema also rejects unmodeled ACLs, security labels, extension ownership, and comments outside captured domain/enum definitions; a PostgreSQL 18 fixture confirms domain and enum ACL changes fail closed. Standalone composites additionally require no storage; their table-only constraints and indexes must be absent. Other modeled relation kinds fail closed. Defaults and stored or virtual generated expressions are captured for every column; their dependencies are not inferred from rendered text. Referenced column, domain, and index-key collations now carry a successor definition digest with exact provider, encoding, deterministic mode, locale fields, ICU rules, stored version, actual provider version, and catalog comment. The `pg_catalog.default` entry also binds the effective database locale and version; impossible provider/locale field combinations fail closed. The adapter checks text size on the server before returning catalog fields; security-labeled or extension-owned collations fail closed. Unreferenced schema collations and collation-owner authorization metadata remain outside this bounded path.

Rows are streamed and checked against the authorized row and retained-byte ceilings before snapshot construction. Oversized reconstructed defaults, generated expressions, index definitions/predicates, option arrays, comments, or CHECK definitions are rejected by server-side byte checks without returning their text. Every connect, transaction, query, stream read, and commit is bounded by the non-resetting operation budget and cooperative cancellation. Failed capture drops the transaction and connection without publishing a snapshot.

The adapter admits ordinary PostgreSQL 18 FOREIGN KEY constraints only when the referenced table is inside the authorized observed scope. It binds each FK to the selected referenced unique index and all three ordered equality-operator arrays using qualified operator signatures. The complete FK family changes successor source identity, and the owner checks referenced-index coherence. Both sides of every FK must have exactly the expected PostgreSQL internal referential triggers, with matching action, firing shape, index, deferrability, and counterpart relation. Incoming FKs from unobserved tables fail closed. PERIOD and unsupported catalog variants remain outside this bounded path.

The transport dependency is pinned to `tokio-postgres =0.7.18` in `Cargo.lock`, the first patched version for [GHSA-3gjw-f78c-vvpw](https://github.com/advisories/GHSA-3gjw-f78c-vvpw). TLS uses `rustls =0.23.45`, which fixes [RUSTSEC-2026-0285](https://rustsec.org/advisories/RUSTSEC-2026-0285). `cargo deny check advisories` passed on 2026-09-25. The [PostgreSQL 18 type](https://www.postgresql.org/docs/18/catalog-pg-type.html), [enum](https://www.postgresql.org/docs/18/catalog-pg-enum.html), [index](https://www.postgresql.org/docs/18/catalog-pg-index.html), [class](https://www.postgresql.org/docs/18/catalog-pg-class.html), and [constraint](https://www.postgresql.org/docs/18/catalog-pg-constraint.html) catalogs define the captured fields.

Run the local PostgreSQL 18 fixture with `CONCEPTWEAVE_PG18_TEST_DSN='host=/tmp dbname=postgres' cargo +1.98.0 test -p conceptweave-postgres-adapter --test postgres18_capture -- --test-threads=1`. Run its live fixtures serially because they share one local PostgreSQL server. Fidelity fixtures retain bounded 60-second operation and 30-second statement budgets; heavy runner load exhausted the former 3-second statement budget even in a serial run. The fixture creates and removes two dedicated schemas. It checks domain/enum, table/column and default, explicit, and nondeterministic ICU collation evidence, CHECK, NOT NULL, PRIMARY KEY and UNIQUE constraint, and index receipts; changed digests after live enum/domain, column-default/comment, CHECK validation, NOT NULL add/validate/drop, PRIMARY KEY and UNIQUE creation, and index-comment changes; stored and virtual generated-column evidence; a unique `NULLS NOT DISTINCT` index; mixed column/expression keys with INCLUDE and a partial predicate; exact quoted whitespace identifiers; same-name enums in separate schemas; input-order-independent identity; row and byte ceilings; exact capture of a Hash index and a B-tree fillfactor change. It distinguishes INITIALLY IMMEDIATE and INITIALLY DEFERRED UNIQUE digests, verifies the internal recheck trigger, and rejects a user trigger or explicit expression statistics target. A live custom-table-access-method fixture verifies fail-closed admission; the identity fixture compares all sequence settings with `pg_sequence` and verifies changed digests after an increment, sequence comment, or generation-mode edit. A separate live FK fixture checks a composite relationship, selected referenced index, equality operators, targeted `ON DELETE SET NULL`, delayed enforcement, stable replay digest, changed digests after changing actions/timing and validating a `MATCH FULL NOT VALID` constraint, and rejection of an out-of-scope referenced table. A separate live collation fixture proves that `ALTER COLLATION ... REFRESH VERSION` changes source identity while the qualified collation name and determinism remain the same. It admits the table again after the user trigger is dropped despite PostgreSQL's stale hint. Without the environment variable, that server test is skipped.

The checked-in `tests/fixtures/grc_shape.sql` contains an anonymized tenant/risk/control/link schema without application rows. Its live PostgreSQL 18 replay verifies four observed tables, one domain, one enum, four foreign keys, exact `conperiod` coordinates for every key and foreign key, an exact constraint receipt, stable digest across observations, changed digest after a column comment edit, and restoration of the original digest after reversing that edit. It compares index key/INCLUDE counts and order, partial predicates, catalog flags, NOT NULL constraint rows, domain base/settings/CHECK rows, and ordered enum labels with fresh PostgreSQL catalog reads. It queries only the dedicated fixture schema through the adapter.

The TCP fixture uses an isolated PostgreSQL 18 instance configured with `ssl=on`, a server certificate for `localhost`, and `hostssl` access only. Set `CONCEPTWEAVE_PG18_TLS_TEST_DSN='host=localhost port=<port> dbname=postgres'`, `CONCEPTWEAVE_PG18_TLS_CA_DER=<DER CA certificate path>`, `CONCEPTWEAVE_PG18_TLS_WRONG_CA_DER=<unrelated DER CA certificate path>`, and `CONCEPTWEAVE_PG18_PLAINTEXT_TEST_DSN='host=localhost port=<plain server port> dbname=postgres'` for the same test command. The plaintext server must have `ssl=off`. The TLS instance must contain an empty `conceptweave_tls_fixture` schema created with plain `CREATE SCHEMA`, because the stock `public` schema carries an ACL and comment that fail closed. It proves that the authorized observation succeeds with the correct CA and host, while an unrelated CA, an IP host absent from the certificate, and a server without TLS all fail. The test is skipped unless all four variables are set.

This path does not admit general relation-bearing schemas. Discovery maps ordinary tables to table concepts and standalone composite relations to separate source-type concept candidates. Any nonempty relational or type-only proposal now requires explicit true-array, type-kind, and collation-definition observation, including a matching composite type row for each proposed table or standalone composite and matching type rows for each domain and enum. An older v3 snapshot with an unobserved or incomplete type-kind family remains representable but cannot become a reviewable proposal. The live composite fixture checks separate attribute candidates, exact column receipts, required alignment decisions, parent validation, steward-review digest binding, durable publication, signed release admission, and pinned client readback; other relation kinds remain outside this bounded path. It does not establish the required complete PostgreSQL adapter, independent approval, hosted Product checks, or same-generation differential over the full model.

Every admitted ordinary table now carries a separate successor storage observation with the resolved `pg_tablespace.spcname` and exact `pg_class.reltablespace = 0` database-default marker. The adapter resolves the default from `pg_database.dattablespace` inside the same read-only transaction; missing or duplicate table storage evidence fails closed. A live PostgreSQL 18 fixture moves an admitted table to a separate tablespace and verifies the changed source digest and marker without rewriting historical v3 identities.

Every admitted table and standalone composite also binds its same-generation `pg_class.relowner` OID and resolved role name in a later successor digest. Missing or duplicate owner evidence fails closed before Discovery promotion. A PostgreSQL 18 fixture changes a table owner without changing its schema or columns, checks the resolved owner against a fresh catalog read, and verifies changed source identity. Role OIDs remain source-local catalog identity, not portable business identity.

Each requested schema now also binds its same-generation `pg_namespace.nspowner` OID and resolved role name in a successor digest. A PostgreSQL 18 fixture proves that changing the schema owner changes source identity and that renaming the owner changes identity while its OID stays fixed. The final digest issues an exact `/schemas/{schema}` receipt only after owner observation, including for an empty schema; unknown schema coordinates cannot borrow another schema's evidence. Explicit schema ACLs and comments fail closed, as do unmodeled security labels and extension membership. Discovery requires this schema-owner family before proposing a semantic model. The owner OID remains source-local evidence.

The live quoted-identifier fixture preserves whitespace, slash, and tilde in observed schema/relation/column/constraint/index/domain/enum names, and verifies distinct receipt coordinates for text that resembles an escaped pointer token.

The column-collation fixture compares the captured database-default collation against PostgreSQL 18's actual provider-`d`, encoding-`-1` catalog row and the current database locale/version fields.

The expression dependency reader resolves PostgreSQL 18 container access from the node's declared result type rather than the container expression's type. Integer array-element and JSON container-access I/O conversions are admitted when their resolved I/O functions and container-access handlers pass the shared catalog checks. A missing element type is valid only as the explicit zero sentinel for a container with no separate element type; malformed, missing, or zero required result/container types fail closed. Session-dependent timestamp-array conversion remains rejected. The initial explicit-ACL admission guard on container-access handlers is superseded by the receipt-bound raw ACL inventory below. These admission checks do not complete canonical expression identity or versioned procedure, ACL, security-label, extension, and initial-privilege evidence.

Referenced explicit functions, operator implementations, I/O functions and container-access handlers now carry a versioned definition inventory from the same transaction. Each entry uses its qualified ordered input signature, qualified return type, reconstructed definition and exact owner role OID/name; procedure OIDs remain lookup keys. Definition text is redacted in routine Debug output. Exact overloaded-signature receipts bind the final source digest, and unknown signatures cannot obtain a receipt. Nonempty Discovery proposals require this inventory; older snapshot constructors remain reproducible but do not claim that evidence. The five owned-database fixture paths change function ownership without changing reconstructed definition text and require a new source digest while preserving older receipts. The earlier customized-ACL rejection is superseded by the access-control successor below. The security-label, initial-privilege and installed-extension omissions are repaired by the successors below; full typed/parsed-expression closure and full same-generation differential acceptance remain outstanding work.

A separate access-control successor binds every referenced procedure's original ACL, preserving catalog NULL, explicit empty arrays, original item order and multiplicity, PUBLIC's zero grantee sentinel, raw role OIDs with optional resolved names, and EXECUTE/grant-option bits. Zero-privilege ACL items are retained even though PostgreSQL aclexplode emits no grant rows for them. Their original role OIDs are checked with native ACL containment before name enrichment; numeric role names and numeric OID fallback candidates cannot establish identity by themselves. ACL items are redacted in Debug output. Procedure-root receipts bind the final digest, and nonempty proposals require the complete access-control inventory. The old definition receipt name remains compatible. Owned-database fixtures cover five reference paths, permission removal, zero-rights items, dangling OIDs, duplicate items, order changes and NULL versus explicit empty ACL.

Referenced-procedure security labels now have a separate successor after ACL evidence. Each observed procedure has a complete provider-to-label map, including observed absence; missing inventories remain distinct. Provider and label text are preserved without trimming or interpretation, empty labels remain observable, duplicate providers and incomplete signature coverage fail closed, and Debug output redacts label material. Capture uses the same bounded read-only transaction and meters source label rows and bytes. Nonzero procedure subobject numbers and oversized labels fail before immutable success. Procedure-root receipts bind the final digest, historical frames remain unchanged, and nonempty proposals require this inventory. The five owned-database reference paths compare exact labels against the native catalog, change and remove labels, preserve prior receipts, reject unknown signatures and reobservation, and exercise malformed subobject numbers and byte limits. The original omission was reproduced at a6fea2e2: the native label changed while the admitted digest did not.

The catalog contract follows [PostgreSQL 18 pg_seclabel](https://www.postgresql.org/docs/18/catalog-pg-seclabel.html): procedure labels use a zero subobject number; provider-owned text is source evidence and does not confer application permissions. The controlled fixture writes only its private database catalog and does not install a label provider or claim validation of provider-specific policy.

Referenced-procedure initial privileges have a separate successor after security labels. Every resolved signature has an observed initial-privilege fact: catalog row absence differs from a present empty ACL, and initialization versus extension origin remains explicit source evidence. The original ACL item sequence, duplicates, PUBLIC, role OIDs with optional names, and EXECUTE/grant-option bits are retained. Current ACL and initial privileges use one bounded ACL reader and native verification of zero-rights items; names never establish role identity. Debug output redacts ACL material. Nonempty proposals require the complete inventory; exact procedure-root receipts preserve older receipts and historical frames.

The controlled five-reference fixture changes only initial privileges while requiring unchanged current ACL, definitions and security-label evidence. It compares native row origin and ACL cardinality, checks source role identities and bits, changes item order and origin, distinguishes present empty ACL from row absence, removes the row to restore the prior digest, and rejects unknown origins, nonzero subobject numbers, NULL ACL elements, multiple dimensions and row-limit overflow before immutable success. The original c16f4c7d omission was reproduced in a private database: native initial privileges changed but the admitted digest did not. The catalog contract follows [PostgreSQL 18 pg_init_privs](https://www.postgresql.org/docs/18/catalog-pg-init-privs.html). Extension origin alone does not prove extension membership or authorize semantic publication; those remain separate acceptance obligations.

A separate installed-extension successor follows initial privileges. Every observed procedure has a complete dependency inventory, including observed absence. Native dependency codes and duplicate automatic edges remain source facts; multiple membership edges are rejected. Referenced extension definitions retain their database-wide names, raw owner role OIDs with optional names, exported-object schemas, relocation flags, exact version text, and original configuration table/filter sequences. Extension and configuration table OIDs are lookup keys; resolved names and relation kinds bind identity. Configuration NULL differs from an explicit empty list, filter text is never executed, and routine Debug output redacts it. Configuration references add catalog evidence only; they do not add business entities or read configuration table rows.

Capture uses the existing bounded read-only transaction and rejects missing targets, nonzero object subidentifiers, unsupported dependency codes, mismatched or noncanonical configuration arrays, NULL elements, unsupported configuration relation kinds, and row/byte-limit overflow before immutable success. Exact procedure-root receipts bind the final successor while earlier receipts and frames remain immutable. Nonempty proposals require this inventory. The five-reference fixture uses real ALTER EXTENSION ADD/DROP FUNCTION and ALTER FUNCTION [NO] DEPENDS ON EXTENSION, compares native extension definitions, changes each definition field and filter text, distinguishes empty/NULL configuration, rejects malformed references and limits, and restores the predecessor digest. Its configuration table lives in the fixture's private database and is examined only through system catalogs.

The original omission was reproduced at 433879d1 with real membership DDL and unchanged admitted digest. The contracts follow [PostgreSQL 18 pg_depend](https://www.postgresql.org/docs/18/catalog-pg-depend.html) and [pg_extension](https://www.postgresql.org/docs/18/catalog-pg-extension.html). Installed version text and dependency membership are source evidence; they do not verify extension binaries or grant semantic publication authority. Full typed/transitive expression closure, full same-generation differential acceptance, owned coverage and protected delivery remain separate obligations.
