# PostgreSQL 18 bounded observation path

`conceptweave-postgres-adapter` consumes a single registry-authorized Source Observation capability. Its connection map holds one current policy binding and credential-bearing `tokio-postgres::Config` per source key. An older binding fails before connection lookup can reach source I/O. Credentials remain adapter-local. This path accepts Unix sockets only. TCP configurations fail before connecting because a verifying TLS connector is not installed.

The adapter opens one `REPEATABLE READ READ ONLY` transaction, fixes `search_path` to `pg_catalog`, sets local server timeouts, and checks the server major version and transaction mode. It verifies every requested schema exists in that transaction. It reads qualified domain base types and collations, type modifiers, array dimensions, null/default state, comments, domain CHECK definitions and validation/enforcement flags, and enum labels in catalog order. It also admits ordinary permanent tables with exact column order, qualified type binding, rendered type text, nullability, comments, and replica-identity mode. Unknown domain constraint kinds fail closed. Catalog OIDs are used only for joins within that transaction; immutable identity uses exact qualified names and observed content.

The table path rejects partitioned/inherited, typed, temporary or unlogged, security-enabled, option-bearing, ACL-bearing, rule-bearing, trigger-bearing, or extension-owned relations. Rule and trigger catalog rows decide admission because `pg_class.relhasrules` and `relhastriggers` can remain true after deletion. It admits local table CHECK constraints with their reconstructed definition and validation, enforcement, and inheritance flags, requiring `pg_class.relchecks` to match captured rows. It captures every ordinary-table `pg_constraint.contype = 'n'` row as a distinct NOT NULL successor fact and requires one for every nonnullable column. It also admits ordinary nondeferrable, validated and enforced PRIMARY KEY and UNIQUE constraints, resolving ordered `conkey` positions to exact columns and checking their backing index name, ordered key shape, lifecycle, and NULL comparison behavior. Constraint comments and security labels, plus FOREIGN KEY, exclusion, and nondefault key-constraint variants, still fail closed. Its index path admits permanent ordinary indexes with column and expression keys, INCLUDE columns, partial predicates, and exact access-method names. Key positions remain distinct from INCLUDE positions; a zero `indkey` entry is captured as the server-rendered expression at that exact position. Index storage and key-level operator-class options are preserved as exact `keyword=value` catalog entries; access-method option bits remain uninterpreted. Index ACLs, security labels, extension ownership, and an explicit index-expression statistics target still fail closed. It captures each key's exact qualified collation and operator class, raw option bits, uniqueness/null semantics, lifecycle flags, resolved tablespace, reconstructed definition, and comment. It also rejects identity, dropped, explicitly collated, ACL-bearing, option-bearing, or missing-value-bearing columns until their complete catalog families are mapped. Other modeled relation kinds fail closed. Defaults and stored or virtual generated expressions are captured for every column; their dependencies are not inferred from rendered text.

Rows are streamed and checked against the authorized row and retained-byte ceilings before snapshot construction. Oversized reconstructed defaults, generated expressions, index definitions/predicates, option arrays, comments, or CHECK definitions are rejected by server-side byte checks without returning their text. Every connect, transaction, query, stream read, and commit is bounded by the non-resetting operation budget and cooperative cancellation. Failed capture drops the transaction and connection without publishing a snapshot.

The transport dependency is pinned to `tokio-postgres =0.7.18` in `Cargo.lock`, the first patched version for [GHSA-3gjw-f78c-vvpw](https://github.com/advisories/GHSA-3gjw-f78c-vvpw). `cargo deny check advisories` passed on 2026-09-24. The [PostgreSQL 18 type](https://www.postgresql.org/docs/18/catalog-pg-type.html), [enum](https://www.postgresql.org/docs/18/catalog-pg-enum.html), [index](https://www.postgresql.org/docs/18/catalog-pg-index.html), [class](https://www.postgresql.org/docs/18/catalog-pg-class.html), and [constraint](https://www.postgresql.org/docs/18/catalog-pg-constraint.html) catalogs define the captured fields.

Run the local PostgreSQL 18 fixture with `CONCEPTWEAVE_PG18_TEST_DSN='host=/tmp dbname=postgres' cargo +1.98.0 test -p conceptweave-postgres-adapter --test postgres18_capture`. The fixture creates and removes two dedicated schemas. It checks domain/enum, table/column, CHECK, NOT NULL, PRIMARY KEY and UNIQUE constraint, and index receipts; changed digests after live enum/domain, column-default/comment, CHECK validation, NOT NULL add/validate/drop, PRIMARY KEY and UNIQUE creation, and index-comment changes; stored and virtual generated-column evidence; a unique `NULLS NOT DISTINCT` index; mixed column/expression keys with INCLUDE and a partial predicate; exact quoted whitespace identifiers; same-name enums in separate schemas; input-order-independent identity; row and byte ceilings; exact capture of a Hash index and a B-tree fillfactor change. It rejects a deferrable UNIQUE, live trigger, and explicit expression statistics target, then admits the table again after the trigger is dropped despite PostgreSQL's stale hint. Without the environment variable, that server test is skipped.

This path does not admit general relation-bearing schemas or TCP sources. It does not establish the required complete PostgreSQL adapter, independent approval, hosted Product checks, or same-generation differential over the full model.
