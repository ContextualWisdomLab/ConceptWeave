# PostgreSQL column identity evidence

## Decision status

Proposed Source Observation repair. This record binds the behavioral RED introduced by `85f2eb0cdd80b6de6983895f598efe5e463da887`; it is not native GREEN, publication authority, or release evidence.

## Problem

The successor schema observation preserves exact column coordinates, qualified type identity, nullability, comments, and an optional source-authoritative column-collation family, but it does not preserve PostgreSQL `pg_attribute.attidentity`.

PostgreSQL 18 defines three materially different catalog states for `attidentity`: the empty value means the column is not an identity column, `a` means `GENERATED ALWAYS`, and `d` means `GENERATED BY DEFAULT`. The identity mode changes write behavior. An identity column receives values from an implicit sequence when no explicit value is supplied; `GENERATED ALWAYS` and `GENERATED BY DEFAULT` differ in whether an ordinary explicit value is accepted without an overriding clause. Identity columns are also automatically `NOT NULL`, but nullability does not encode the identity mode and identity does not itself guarantee uniqueness.

Consequently, two otherwise-identical observed schemas can currently reuse one governed v3 identity even when one reports `attidentity='a'` and the other `attidentity='d'`, or when one has an identity column and the other does not. That collapses source schema behavior that a data architect can observe and that downstream proposal/validation work may need to explain.

## Constraints

- Keep the existing v3 constructor and digest reproducible when the identity family is unobserved. Historical receipts and already-defined digest domains must not change meaning.
- Treat `attidentity` as source-authoritative column state. Do not infer it from integer type, `NOT NULL`, primary-key/unique membership, index shape, default text, sequence naming, or a `nextval(...)` rendering.
- Catalog OIDs are capture-time join coordinates only and must not become governed identity.
- When the family is claimed as observed, every bounded relation column needs one exact observation so explicit not-identity remains distinguishable from family-unobserved.
- Duplicate exact column coordinates are contradictory evidence and fail closed. Input ordering is not semantic identity.
- The `attidentity` family does not invent the attached sequence configuration. Sequence start/increment/min/max/cache/cycle/ownership semantics require a separately versioned, source-authoritative evidence family before ConceptWeave can claim them.
- PostgreSQL inheritance and partition rules remain source facts, not inferred topology. Identity properties are independent across ordinary inheritance children, while partitions inherit the partitioned table's identity properties and cannot define their own. A later topology/adapter slice must capture enough source evidence to validate those relationships instead of guessing from relation names.

## Alternatives considered

### Add an `identity` field directly to `ColumnObservationV3`

Rejected. `ColumnObservationV3` participates in the already-published successor digest framing. Mutating the frozen value object would silently change the meaning of existing v3 identities and constructors.

### Infer identity from default or sequence evidence

Rejected. `attidentity` is the direct PostgreSQL declaration authority. A sequence-backed default is not equivalent to an identity column, and naming conventions are not source truth.

### Ignore identity because it is operational rather than semantic

Rejected. `GENERATED ALWAYS` versus `GENERATED BY DEFAULT` changes admissible writes and override behavior. A governed immutable schema observation that collapses the two cannot faithfully explain source behavior.

### Add an optional observed column-identity family

Selected. Introduce a dedicated `ColumnIdentityObservation` family with explicit not-identity, generated-always, and generated-by-default states. Attach it through a domain-separated successor digest layer while leaving the original constructor's digest unchanged when the family is unobserved.

## Behavioral contract

The RED `crates/conceptweave-observation/tests/column_identity_contract.rs` requires:

- `GENERATED ALWAYS` and `GENERATED BY DEFAULT` for the same exact column to produce different governed identities;
- explicitly observed not-identity to remain distinct from an unobserved identity family;
- complete coverage of every bounded relation column whenever the family is claimed;
- duplicate exact column coordinates to fail closed; and
- input-order permutations of the same complete identity evidence to remain digest-identical.

The production repair should expose beginner-readable public rustdoc, retain exact schema/relation-kind/relation/column coordinates, and use a separate digest domain such as `conceptweave.postgres_schema_snapshot.v3.column_identity.v1`.

## Adapter obligation

The later PostgreSQL adapter must read `pg_attribute.attidentity` for every bounded column inside the same authorized `REPEATABLE READ READ ONLY` catalog snapshot when claiming this family. It must map only the documented empty/`a`/`d` states and fail closed on unexpected values rather than converting them through heuristics. Identity sequence properties remain outside this family until their own immutable/versioned contract exists.

No source transaction may remain open while an LLM or other long-running external computation executes.
