# PostgreSQL column identity evidence

## Decision status

Source repair implemented; exact-head native/Product acceptance remains pending. The original column-identity behavioral RED `85f2eb0cdd80b6de6983895f598efe5e463da887` led to production commits `69a86d2a52fc0f75360f6a48a4549154511fa92b` and `95f7f81f9bed07ebd17c8a9d3d27187b0c94fa48`. A follow-up review `5188419794` found that the observed identity family still admitted the catalog-impossible combination of `attidentity in {'a','d'}` with nullable column evidence. Behavioral regression commit `bd6da911262a70a0a6d27ba439848831062813fb` covers that contradiction and production commit `00b166bfb47473b567bef3c5ab2f800327afda34` makes the shared canonicalizer fail closed. None of these coordinates is native GREEN, publication authority, or release evidence.

## Problem

The predecessor schema observation preserved exact column coordinates, qualified type identity, nullability, comments, and an optional source-authoritative column-collation family, but did not preserve PostgreSQL `pg_attribute.attidentity`.

PostgreSQL 18 defines three materially different catalog states for `attidentity`: the empty value means the column is not an identity column, `a` means `GENERATED ALWAYS`, and `d` means `GENERATED BY DEFAULT`. The identity mode changes write behavior. An identity column receives values from an implicit sequence when no explicit value is supplied; `GENERATED ALWAYS` and `GENERATED BY DEFAULT` differ in whether an ordinary explicit value is accepted without an overriding clause. Identity columns are implicitly `NOT NULL`, but nullability does not encode the identity mode and identity does not itself guarantee uniqueness.

Consequently, two otherwise-identical observed schemas could reuse one governed v3 identity even when one reported `attidentity='a'` and the other `attidentity='d'`, or when one had an identity column and the other did not. After the family was added, a second inconsistency remained: the canonicalizer could accept an identity observation for the same bounded column that `ColumnObservationV3` reported as nullable. PostgreSQL cannot produce that pair as a coherent identity-column declaration, so preserving it as governed immutable evidence would turn contradictory same-snapshot catalog facts into apparent source truth.

## Constraints

- Keep the existing v3 constructor and digest reproducible when the identity family is unobserved. Historical receipts and already-defined digest domains must not change meaning.
- Treat `attidentity` as source-authoritative column state. Do not infer it from integer type, `NOT NULL`, primary-key/unique membership, index shape, default text, sequence naming, or a `nextval(...)` rendering.
- Treat nullability as an independently observed column fact. It can invalidate a contradictory identity declaration, but it cannot invent one.
- Catalog OIDs are capture-time join coordinates only and must not become governed identity.
- When the family is claimed as observed, every bounded relation column needs one exact observation so explicit not-identity remains distinguishable from family-unobserved.
- Duplicate exact column coordinates are contradictory evidence and fail closed. Input ordering is not semantic identity.
- A `GENERATED ALWAYS` or `GENERATED BY DEFAULT` observation for a bounded column with `nullable() == true` is contradictory source evidence and fails closed as `column_identity_nullability`. Explicit not-identity remains valid for nullable columns.
- The `attidentity` family does not invent the attached sequence configuration. Sequence start/increment/min/max/cache/cycle/ownership semantics require a separately versioned, source-authoritative evidence family before ConceptWeave can claim them.
- PostgreSQL inheritance and partition rules remain source facts, not inferred topology. Identity properties are independent across ordinary inheritance children, while partitions inherit the partitioned table's identity properties and cannot define their own. A later topology/adapter slice must capture enough source evidence to validate those relationships instead of guessing from relation names.

## Alternatives considered

### Add an `identity` field directly to `ColumnObservationV3`

Rejected. `ColumnObservationV3` participates in the already-published successor digest framing. Mutating the frozen value object would silently change the meaning of existing v3 identities and constructors.

### Infer identity from default, nullability, or sequence evidence

Rejected. `attidentity` is the direct PostgreSQL declaration authority. A sequence-backed default is not equivalent to an identity column, naming conventions are not source truth, and `NOT NULL` is necessary for an identity column but is not sufficient evidence that the column is an identity column.

### Ignore identity because it is operational rather than semantic

Rejected. `GENERATED ALWAYS` versus `GENERATED BY DEFAULT` changes admissible writes and override behavior. A governed immutable schema observation that collapses the two cannot faithfully explain source behavior.

### Accept contradictory identity/nullability evidence and leave it to transport

Rejected. Both facts already exist inside one bounded immutable representation before transport. Once the family is claimed as observed, the domain layer has enough source evidence to detect the contradiction deterministically. Allowing the impossible pair to survive would weaken the governed evidence boundary.

### Add an optional observed column-identity family with same-snapshot consistency validation

Selected and implemented. `ColumnIdentityObservation` carries explicit not-identity, generated-always, and generated-by-default states. The family attaches through the domain-separated `conceptweave.postgres_schema_snapshot.v3.column_identity.v1` digest layer while the original constructor's digest remains unchanged when the family is unobserved. The canonicalizer additionally resolves the exact bounded column and rejects identity mode when that column is observed nullable.

## Behavioral contract and implementation

The original RED `crates/conceptweave-observation/tests/column_identity_contract.rs` requires:

- `GENERATED ALWAYS` and `GENERATED BY DEFAULT` for the same exact column to produce different governed identities;
- explicitly observed not-identity to remain distinct from an unobserved identity family;
- complete coverage of every bounded relation column whenever the family is claimed;
- duplicate exact column coordinates to fail closed; and
- input-order permutations of the same complete identity evidence to remain digest-identical.

Follow-up behavioral regression `bd6da911262a70a0a6d27ba439848831062813fb` adds a realistic contradictory fixture: the bounded column is observed nullable while `attidentity` is `GENERATED ALWAYS` or `GENERATED BY DEFAULT`. Both cases must fail as `column_identity_nullability`; the same nullable column with explicit not-identity remains a positive control.

Production commit `69a86d2a52fc0f75360f6a48a4549154511fa92b` adds the isolated source-authoritative family, exact coordinate validation, completeness and duplicate checks, deterministic ordering, and domain-separated digest encoding. Commit `95f7f81f9bed07ebd17c8a9d3d27187b0c94fa48` integrates the module into `PostgresSchemaSnapshotV3`, adds the explicit constructor/consuming method/accessor, initializes the family as unobserved on every legacy-compatible constructor path, and fixes the canonical optional-family order to type/array -> column collation -> column identity -> constraint timing/period.

Production follow-up `00b166bfb47473b567bef3c5ab2f800327afda34` changes only the identity canonicalization seam: after resolving the exact relation it resolves the exact bounded column, preserves the existing coordinate failure for unknown columns, and rejects identity mode when `ColumnObservationV3::nullable()` is true. It does not infer identity from nullability, change the digest encoding, change the public API, or reject nullable non-identity columns.

The source-level RED and repair are structurally narrow, but structural inspection is not a substitute for repository-pinned Rust execution.

## Adapter obligation

The later PostgreSQL adapter must read `pg_attribute.attidentity` and `attnotnull` for every bounded column inside the same authorized `REPEATABLE READ READ ONLY` catalog snapshot when claiming this family. It must map only the documented empty/`a`/`d` identity states and fail closed on unexpected values rather than converting them through heuristics. The immutable representation must reject an identity mode paired with nullable column evidence rather than attempting to normalize the contradiction. Identity sequence properties remain outside this family until their own immutable/versioned contract exists.

No source transaction may remain open while an LLM or other long-running external computation executes.
