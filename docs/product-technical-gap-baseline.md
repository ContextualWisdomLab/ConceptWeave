## Canonical boundary

ConceptWeave owns `observe -> discover -> propose -> align -> validate -> review -> publish`, ontology/semantic-layer generation and validation, governed immutable semantic releases, and the released client contract. `semantic-data-portal` owns catalog/governance/consumption, `context-graph-contracts` owns interoperability contracts, `enterprise-architecture-core` owns EA truth, and `contextual-orchestrator` owns production LLM routing. Product-domain truth stays with its canonical owner; consumers use released/versioned contracts rather than source copies, cross-service SQL, or mutable sibling heads.

The relational discovery seam now builds a deterministic review draft from an immutable observed snapshot. Each proposed table concept carries its table receipt and observed primary-key columns; each source column is a separate physical-mapping candidate with its exact column receipt and qualified type. Each proposed relationship carries its foreign-key receipt, endpoint concepts, ordered column pairs, reference behavior, and validation/enforcement state. Schema-scoped domains and enums retain their complete source definitions and exact receipts as constraint and dimension candidates, including a type-only schema. Standalone composite types become separate concept candidates with exact relation receipts; each attribute is a separate physical-mapping candidate with its own column receipt and parent validation. They are not table concepts or automatic business truth. A draft and its candidates remain inferred; source names, types, and foreign keys do not become business truth. Unsupported relation kinds, references outside the observed set, unobserved catalog families, and incomplete relationship state fail closed. The anonymized GRC-shaped PostgreSQL 18 replay verifies four concepts, thirteen field mappings, four relationships, two source-type candidates, stable proposal identity on replay, and a changed identity after source metadata changes. It also compares the captured table, column, index, constraint, and domain/enum inventories with fresh PostgreSQL catalog queries, including exact column coordinates/type/nullability/comments, index access methods/definitions/lifecycle flags, ordered key/INCLUDE columns and partial predicates, ordered foreign-key endpoints/columns, actions/match/timing/validation state, referenced backing indexes and ordered comparison operator signatures, NOT NULL constraint rows, domain base/settings/CHECK rows, and ordered enum labels. This bounded fixture comparison does not establish the full same-generation differential named below. Run it with `CONCEPTWEAVE_PG18_TEST_DSN='host=/tmp dbname=postgres' cargo +1.98.0 test -p conceptweave-postgres-adapter --test postgres18_capture postgres18_anonymized_governance_shape_replays_without_business_rows -- --exact`.

The built-in lookup is limited to types actually used by captured columns and domains. Missing or duplicate type-owner observations fail admission; the live fixture checks domain and enum changes separately. The admitted column shape does not represent nondefault physical storage, compression, or statistics settings. A PostgreSQL 18 RED/GREEN fixture demonstrates that `ALTER COLUMN ... SET STORAGE EXTERNAL`, `SET COMPRESSION pglz`, and `SET STATISTICS 500` previously remained admitted without changing source identity. The adapter now compares column storage with its type default and rejects explicit compression or statistics settings before constructing a snapshot. Modeling these settings would require a separate successor evidence family; the bounded adapter fails closed meanwhile.

Dropped `pg_attribute` rows remain physical tombstones but are not SQL-visible columns. The adapter excludes them from the observed column set without renumbering surviving `attnum` coordinates. A PostgreSQL 18 fixture verifies a retained ordinal gap, the surviving index key, and source receipts for live versus dropped columns.

A PostgreSQL 18 fixture now captures quoted identifiers with leading/trailing whitespace and embedded `/` and `~` across schema, table, columns, primary-key index/constraint, domain, and enum. It resolves exact receipts for each and verifies that literal pointer-like column text cannot collide with JSON Pointer-escaped coordinates. This is bounded identifier/receipt evidence, not the complete same-generation catalog differential.

The existing aggregate validation rejects a replica-identity index flag on a nonunique index and rejects partial, deferred, expression-key, or nullable-key shapes before immutable snapshot construction. The independent relation-level replica-identity mode remains source evidence even when its selected index has been dropped. The contract keeps nullable INCLUDE payloads outside the NOT NULL key requirement, while the GRC-shaped live fixture checks a selected replica-identity index and exact relation mode.

PostgreSQL 18 `NOT ENFORCED` foreign keys are now observed with explicit false validation and enforcement state. The adapter expects no referential-integrity triggers for those keys while still requiring the complete trigger set for enforced siblings; an unexpected trigger fails capture. A live fixture verifies both states, the source receipt, changed source identity after enforcement, and an inferred Draft relationship proposal rather than authoritative truth.

Its source receipt resolves, and replacing it with an enforced CHECK changes snapshot identity. PostgreSQL 18 rejects `NOT ENFORCED` for ordinary NOT NULL, UNIQUE, and PRIMARY KEY constraints; the adapter keeps those classes fail-closed on impossible enforcement states.

The alignment seam requires an explicit map or exclusion decision, with a rationale, for every candidate of one exact proposal revision, including each field mapping. Its deterministic validator checks source digest binding, unique proposed semantic identities, that each mapped field belongs to an included concept, and that each mapped relationship keeps both endpoint concepts. The result records how many candidates, identities, fields, and relationships passed those checks. A validated candidate remains inferred until a separately authorized steward decision. The PostgreSQL 18 fixture exercises twenty-three mapped candidates, replay stability, and both excluded-parent and excluded-endpoint failures; a server-free type-only fixture checks decision completeness, stale revisions, and duplicate identities. Structural validation alone does not establish business meaning or authorize publication.

The offline Client now requires an exact, independently configured manifest digest before a release can enter authoritative use. The digest binds identity, versions, publication/truth state, artifact digest, provenance, and concept IDs; superseded predecessors remain subject to the same trust check. Production stewardship and protected key/pin distribution remain unfinished.

The Governance successor now turns a validated alignment into a reviewed proposal only after an injected authority adapter authorizes the exact alignment digest and returns an audit receipt. Publication derives canonical artifact bytes, artifact digest, release, and independent-distribution manifest pin from that review. The PostgreSQL 18 GRC-shaped fixture checks deterministic replay, denial, unpinned rejection, signed pinned client admission, and tampered-artifact rejection. `contracts/governed-semantic-artifact-v2.md` and `contracts/signed-release-manifest-v1.md` record the current byte formats. The fixture authority is not a production steward-authentication service; protected storage deployment, key/pin distribution, and deployed cross-language clients remain unimplemented.

The first publication encoding omitted the field-to-concept and relation-to-endpoint links after validation even though validation had checked them. The validated alignment now retains both maps, and the artifact serializes their complete candidate-ID topology in deterministic order. The PostgreSQL 18 fixture reads the detached bytes back and checks all thirteen field parents and four relation endpoint pairs against the validated model. This keeps the published relationship and physical mapping structure reviewable without reconstructing it from mutable source metadata.

A second boundary check found that alignment also discarded the discovery proposal's exact source details: field names/types/nullability and relation column pairs/reference behavior could not be recovered from the v1 artifact. The validated alignment now retains the immutable proposal, and artifact v2 encodes the complete proposed relational source details, including table/field metadata, ordered FK pairs and behavior, and schema-scoped domain/enum observations. The PostgreSQL 18 fixture decodes these facts from detached bytes and checks them against the original proposal. They remain observed evidence, never automatically promoted to business truth.

The pure in-memory publication constructor could issue two `Published` releases with the same ID and different artifact digests. The local `FilePublicationStore` now makes durable issuance the only public publication path: a protected existing directory, a synced read-only staging record, atomic no-replace hard link, and directory sync precede success. Identical retries and conflicting same-ID reviews fail; readback requires an independently pinned release, rejects nonregular final entries, caps the record read, and verifies stored manifest fields plus artifact bytes. This proves local single-directory issuance, not a deployed multi-host publication service, protected key/pin distribution, or steward authentication.

## Current Source Observation authority

The converter chain retains exact definition/owner/current-ACL/config/security-definer/leakproof/strictness/volatility/parallel-safety/planner-support/cost/function-shape facts, raw nullable `pg_proc.proargmodes`, raw nullable `pg_proc.proargnames`, raw nullable `pg_proc.protrftypes`, immutable raw converter-root lineage, converter-function extension membership, complete auto-extension dependency sets, complete security-label maps, converter-function initial privilege baselines, and independent transform-object extension membership.

The `pg_init_privs` successor is recovery evidence distinct from current `pg_proc.proacl`. It preserves row absence versus presence, exact `privtype`, complete object-level initial EXECUTE ACL, source-array order, and multiplicity. Existing catalog damage can leave ACL role OIDs dangling; Source Observation preserves those nonzero OIDs rather than dropping entries or converting OIDs to role-name strings.

Resolved role identity remains `(role_oid, role_name)` from one source generation. Review `5256559272` on pre-finding exact head `a82dced2a154e1ff105864309a74559255898bbc` found that successful role lookup had collapsed identity to name alone even though PostgreSQL `AclItem` stores grantee/grantor as OIDs and `pg_authid` stores OID and `rolname` separately. Structural RED `b1c8fef6a526b22566b65d8f7962c3af0ebd2031` and production repair `52e1c12d5e592e624d8d55badbdc24c52b428a00` retain exact resolved OIDs privately, move material framing to `.material.v2`, and commit both OID and name without exposing numeric resolved OIDs through routine API or `Debug`.

A separate source-fidelity defect was found at review `5256811598` on exact pre-finding head `69315444d91690886d165a2a9dbde2b193e786ca`. This module used `str::trim().is_empty()` for resolved ACL role names and converter schema/function names. PostgreSQL 18 defines role names by SQL identifier rules; delimited identifiers may contain arbitrary characters except NUL and can contain spaces. The trim-based predicate therefore rejected legal catalog identifiers such as a quoted whitespace-only role, schema, or function name before immutable observation.

Structural RED `650a77aed375798ac2b241bc93ab3dc7cd5e328e` changes the retained contract to accept whitespace-only quoted identifier content while preserving it byte-for-byte, and still requires rejection of zero-length identifiers and NUL content. Production repair `74aa0c47f8ec30ccc824831383e7c6dcf0b09e99` replaces trim-based validation in that bounded module with PostgreSQL-identifier validation. ACL OID identity, source order, multiplicity, recovery evidence, and digest semantics are otherwise unchanged.

Routine grant/material diagnostics remain privacy-conscious. Resolved role names, PUBLIC/unresolved shape, grant option, counts, and immutable digest remain available; numeric resolved OIDs are private identity material and dangling OIDs remain exposed only by receipt-bound recovery-validation accessors. Exact OID identity participates in equality/order and digest identity without becoming routine product API. Source names are not trimmed or normalized: quoted PostgreSQL identifier content remains exact evidence.

Earlier repairs remain in force: complete material readback, source-order preservation, repeated ACLITEM multiplicity, dangling-role representability, canonical sorted/deduplicated remediation OID sets, non-forgeable receipt-bound recovery validation, exact material/provenance binding, and raw-OID Debug redaction. Derived remediation sets may sort/deduplicate dangling OIDs, but they never reorder or deduplicate the source ACL.

Focused doctoring is `docs/doctoring/postgresql-index-exclusion-constraint-operator-procedure-transform-converter-initial-privileges-integrity.md`; damaged-role and recovery-validation details remain in the neighboring dangling-role and recovery-validation doctoring documents.
