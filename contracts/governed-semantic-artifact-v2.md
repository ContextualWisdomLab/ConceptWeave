# Governed semantic artifact v2

This successor extends [v1](governed-semantic-artifact-v1.md) with exact relational source facts that support the reviewed candidates. A v1 artifact and v2 artifact have different domain tags and digests. No v1 artifact is rewritten in place.

All text and blobs use an unsigned 64-bit big-endian byte length followed by exact UTF-8 or raw bytes. Counts are unsigned 64-bit big-endian. Optional values start with byte `0` for absent or `1` for present. Present text then uses ordinary text framing; present lists use a count and elements in source order. Booleans use byte `0` or `1`. Present signed/unsigned 32-bit values use four big-endian bytes after the presence byte. The complete artifact is bounded to 16 MiB.

1. `text("conceptweave.governed_semantic_artifact.v2")`, then release ID, contract version, and ontology version as text.
2. `blob(alignment)`. The alignment begins with `text("conceptweave.validated_alignment.v2")`, proposal ID, source digest, candidate count, and each candidate's v1 decision/evidence record in candidate-ID order. It then carries the four v1 validation counts and the two complete candidate-ID topology maps (fields to parent concepts; relations to both endpoint concepts), each sorted by candidate ID.
3. The alignment continues with `text("conceptweave.relational_source_details.v1")` and three source-detail collections:
   - Concepts sorted by candidate ID: candidate ID, exact schema and table names, optional source comment, optional ordered primary-key column names, then fields in source order. Each field has candidate ID, source column name, PostgreSQL display type, qualified type schema/name, one-based ordinal as a count, nullability byte, and optional source comment.
   - Relations sorted by candidate ID: candidate ID, source and target concept candidate IDs, source constraint name, ordered local/referenced column-name pairs, then six bytes for update action, delete action, match type, deferrability, validation, and enforcement. The optional ordered local-column subset for `ON DELETE SET NULL` or `SET DEFAULT` follows. Action tags: NoAction `0`, Restrict `1`, Cascade `2`, SetNull `3`, SetDefault `4`. Match tags: Simple `0`, Full `1`, Partial `2`. Deferrability tags: NotDeferrable `0`, InitiallyImmediate `1`, InitiallyDeferred `2`.
   - Source types sorted by candidate ID: kind byte `0` for Domain or `1` for Enum, then candidate ID. A domain records exact schema/name, qualified base-type schema/name, optional type modifier, optional array dimensions, optional qualified collation (presence then two texts), optional NOT NULL state (presence then Boolean), optional server-rendered default, ordered check constraints (name, server-rendered definition, validated/enforced bytes), and optional source comment. An enum records exact schema/name, labels in PostgreSQL comparison order, and optional source comment.
4. After the alignment blob, steward ID, review rationale, immutable audit receipt ID, and alignment digest are text, in that order.

The artifact preserves source facts as observation, not approved business meaning. Only explicitly mapped candidates represent the reviewed model; excluded candidates and their source facts remain present for audit. The authority adapter must authenticate and authorize the exact review request and issue an immutable audit receipt. Protected pin distribution and durable immutable storage remain separate production responsibilities.
